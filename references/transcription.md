# 来源、转写与校对细节

## 来源优先级与记录

用户提供的完整材料、官方完整音视频、官方逐字稿和官方节目说明互相印证；第三方 SRT/ASR 作为待校对材料。记录每项材料的 URL/文件、类型、覆盖范围和获取时间。剪辑视频与完整播客时长不同，不能共用时间戳。

小宇宙公开页面曾可从 `__NEXT_DATA__` 的 `props.pageProps.episode` 读取 `title`、`shownotes`、`duration`、`pubDate`、`enclosure.url`；这是实现细节，先核对当前实际返回，不能假定永久有效。名为 `transcript` 的字段可能只是 mediaId，并不包含全文。官方 RSS 可补全期号和音频来源。仅使用有权访问的材料，不编造隐藏接口。

技术访谈中，名称相近的人可能不是同一人。用官方嘉宾介绍、任职时间和完整上下文辨别，不能把全库同音词统一成一个名字。

## 可选的中间数据

用 JSON 数组保存段落，有利于把排版和角色从文本替换逻辑中分离：

```json
[
  {
    "speaker": "主持人姓名",
    "role": "host",
    "source_file": "episode.srt",
    "source_segment": "18-21",
    "start_seconds": 125.4,
    "time_basis": "srt",
    "original": "原始识别文字",
    "edited": "校对后的文字",
    "review": "checked-against-audio"
  }
]
```

无时间时使用 null，不填估算值；说话人不确定就记录待核对。字幕时间提供定位，不代表字幕文字正确。原始材料保留不改，便于回溯。

## 音频与 ASR

先检查现有 ffmpeg、转写工具和模型；根据录音语言、时长、硬件选择已有工具。不要无故重装环境、下载大模型或把音频上传到未经用户授权的新服务。

已取得可读取的音频 URL 后，可用 ffmpeg 直接截取疑点片段，时间应扩展到前后完整问答。以下是命令参数示意，实际运行用参数数组并替换占位值：

```text
ffmpeg -hide_banner -v error -nostdin -n -ss 00:10:00 -i AUDIO_URL -t 00:02:00 -ar 16000 -ac 1 -c:a pcm_s16le clip.wav
whisper-cli -m MODEL_PATH -f clip.wav -l zh -otxt -osrt -of clip-asr
```

`-n` 防覆盖已有片段。URL 可能过期；请求失败时回到原来源更新链接。ASR 输出有时是繁体字、包含重复循环和术语错听；简繁转换与推理参数调整都不能替代内容核对。GPU 不兼容时诊断实际报错，再考虑 CPU 或已有替代工具，不能预设必须使用某种显卡和版本。

全文转写从完整录音生成，保留分段及时间；只重转疑点片段时，将片段内时间加上截取起点才能对应全片。音频真正听不清时保留“听不清”等标记，不补造内容。

## 编辑核对重点

- 核心断言：是否、能否、因果、例外、数值和比较对象不能在润色中改变。
- 角色：自我介绍、上一句称呼、追问回应和声音共同判断。问句也可能是嘉宾反问。
- 次序：官方文章出现主题重排时，先定位到音频/字幕，再恢复录音顺序。低置信匹配、时间大幅回退和漏配段落逐项复核。
- 覆盖：保留段落应覆盖实际讨论；清理广告、口吃和确证重复不等于删除不感兴趣的主题。
- 术语：使用小范围、上下文限定的修改；英文词界匹配，逐项查看修改差异。不能用子串替换将 `topic` 误改为含 `OpenAI` 的新词。
- 洞察：总结来自嘉宾论述，保留其条件和边界；主持人的观点不要归给嘉宾。

交付说明示例：“全文文字校对，针对 5 处错听回听音频；时间使用原字幕。”只有实际完成对应检查才能这样写。
