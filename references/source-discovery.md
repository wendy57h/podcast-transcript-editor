# 寻找播客音频与完整文字稿

用户只提供小宇宙等平台的链接、节目名或嘉宾时，从这里开始。目标是取得**同一期完整音频，以及覆盖全程讨论的文字材料**；摘要、精读和金句只能辅助定位。全文允许忠实清理口吃和非内容性重复，但不能删掉论证、例子、追问和限制条件来冒充全文。

## 1. 锁定单集，沿官方链接找材料

1. 将分享链接解析到实际单集页面。小宇宙的 `/podcast/` 是节目入口，`/episode/` 才是单集；从节目页进入对应一期，记录其稳定页面链接。
2. 核对节目名、嘉宾、期号、日期、时长和开场。标题可能跨平台改写；不能只凭同一个嘉宾认定同一期。区分上下集、加长版、剪辑版和预告，选定一个版本作为时间轴基准。
3. 阅读完整 shownotes，不只看搜索摘要。展开折叠区，检查“全文、文字稿、逐字稿、字幕、资料、公众号、官网、RSS”等入口，打开实际外链及附件。章节时间表和节目简介自身通常不构成逐字稿。
4. 顺着节目官方主页、主播主页或 shownotes 找官方站点、公众号和视频账号。多篇连载逐篇收齐，并核对上下篇接续；转载或精编文章保留来源身份，不因挂着“全文”就直接采用。

## 2. 找到可使用的完整音频

按当前页面实际能力选择路径，不依赖某个固定下载站或猜测接口。

| 入口 | 具体做法 | 检查点 |
| --- | --- | --- |
| 小宇宙单集网页 | 先检查播放器、页面源代码及公开结构化数据。若存在 `script#__NEXT_DATA__`，解析其 JSON，查看 `props.pageProps.episode` 下的 `title`、`duration`、`pubDate`、`shownotes`、`enclosure.url` | 这是页面实现细节；字段不存在就转其他路径，不能把 HTML 正文当音频 |
| 节目官方 RSS | 从节目页面或主播官网寻找 RSS，解析对应 `<item>` 的 `<enclosure url="…">`，用标题、GUID、日期及内容核对单集 | RSS 可能分页或仅保留近期单集；当前 feed 没找到不等于节目不存在 |
| 官方视频/其他播客平台 | 查看同一期完整视频或公开提供的下载/导出入口；工具可读取时取得音轨 | 核对时长和实际内容。音频版、视频版有广告或剪辑差异时，分别保存时间轴 |
| 用户已有材料 | 使用用户提供的原始文件或其有权导出的完整录音 | 确认不是试听、损坏文件或录屏截断 |

小宇宙的 `transcript` 字段可能只是 `{"mediaId": "…"}`；这表示一个资源标识，**不表示已经拿到文字稿**。不要据此猜造隐藏的转写接口。上述页面字段于 2026-10-24 对一个公开单集抽查可见，不构成长期接口承诺。

取得音频 URL 后，用当前网络/下载工具保存原始媒体；请求失败先检查 HTTP 状态、登录要求和链接是否过期，再返回原页面或 RSS 刷新一次。URL 后缀和 HTTP 200 都不能证明成功：检查返回类型，防止下载到登录页；用播放器或 `ffprobe` 检查可解码性、实际时长及首尾内容。不要把带签名的临时 URL 或凭据写进公开文档。

## 3. 寻找现成全文，而不是摘要

沿以下顺序查找；已有可信完整材料时不必重复搜索。每条候选都打开正文，再决定能否使用。

1. **官方全文**：先查 shownotes 外链、节目官网、主播官方公众号和附件。检索同一期的逐字稿、访谈实录及文字版，注意文章是否标注删节、重排或“部分内容”。官方来源也可能只是编辑精华。
2. **RSS 中的转写附件**：检查对应 `<item>` 是否有 Podcasting 2.0 的 `<podcast:transcript>`；读取其 `url`、`type` 及可用语言，下载实际 TXT/HTML/SRT/VTT/JSON 内容。不同 feed 可使用不同 namespace 前缀，应按 namespace URI 解析；没有该标签不等于全网没有全文。
3. **同期完整视频字幕**：检查官方 B 站、YouTube 等账号中对应的完整视频。YouTube 有字幕的视频可从说明中的“Show transcript”查看文字；B 站等平台按当前页面实际可用的字幕功能读取。记录人工字幕或自动字幕的来源、语言和时间基准。字幕不是精读，但仍可能漏段或错听。
4. **第三方全文**：在 Podwise 等可访问服务或转载站查同一期的 Transcript/转写正文，区分 Summary、Takeaways、思维导图和章节概述。Podwise 的产品文档将 Transcript 与总结分开；它的存在不保证该单集已处理、当前账号可读或可导出。
5. **检索补充**：用完整标题定位，再换嘉宾＋节目＋期号检索。示例中的花括号应换成实际名称，各组合分开尝试：

   ```text
   "{单集完整标题}" "文字稿"
   "{节目名}" "{嘉宾}" "逐字稿"
   "{节目名}" "{期号}" "访谈实录"
   site:mp.weixin.qq.com "{节目名}" "{嘉宾}"
   site:podwise.ai "{节目名}" "{嘉宾}"
   "{episode title}" transcript
   ```

遇到分页、懒加载、“展开全文”、上下篇、接口分页或导出功能，取齐所有可访问部分。浏览器提取工具可能只返回当前屏幕或截断长文；检查工具的截断提示、总页数/条目数和最后一段。Podwise 已授权 MCP 等工具若支持分页转写，应逐页读到终点；不能把第一页当完整结果。

Apple Podcasts 等客户端中能看见转写，不代表当前环境可以完整导出；创作者后台的下载能力也不等于普通听众权限。读取受限时记录具体结果，尝试已有授权的导出或另一公开来源；不替用户购买服务，不把全文获取失败降级成用摘要扩写。

## 4. 对全文做覆盖核验

把**来源可靠性、覆盖完整性、文字准确性**分别记录。官方稿可能删节，第三方稿可能完整却错听，完整音频的 ASR 也可能漏掉整段。

- **首尾**：对照真实开场与实质讨论结束，排除只有导语、前几分钟试听、前半篇或缺失结尾的材料。音乐、静音和广告不必强行转写，但需解释与总时长的差额。
- **全程范围**：带时间字幕检查每段起止、顺序、重叠和中间空档；只看“首个时间很早、末个时间接近结束”不能证明中间完整。抽查空档原音频，区分静音、广告、漏识别及转写任务失败。
- **话题对应**：将官方章节/时间表逐项对照正文，有疑点时回听原音频；每个话题不仅应有标题，还应有对应问答、论证和例子。无官方章节时按实际录音建立话题清单。
- **正文性质**：检查是否连续保留双方问答及细节。只有要点列表、金句和编者概述的材料即使很长、标题写着“全文”，也不能当作转写稿。
- **无时间稿**：对照首尾、各话题转折和分布于全程的音频片段；无法确认的区间列出缺口。字数/时长比例只能提示异常，不设统一阈值证明完整；局部抽查也不能说成逐句全程核对。

先标“完整性待核验”；核对支持全程覆盖且已处理发现的缺口后，才标“覆盖已核验”，同时写清依据和抽查范围。发现只有节选就继续找全文或从音频补齐，并逐段保留来源；不能用 AI 编写缺失问答填洞。

## 5. 没有现成全文：从完整音频转写

查过官方入口、同期字幕及可访问全文候选仍无完整材料，且已取得完整音频时，转入 [transcription.md](transcription.md) 的 ASR 流程。不要无限搜索，也不要因为文字未公开就止步于摘要。

- 用现有可用 ASR 转写**整个节目**，保留原始结果、分段和时间。长音频按工具限制分块，记录每块实际起止与成功状态；必要的重叠用于对齐，合并时恢复全局时间并只去除确认重复的内容。
- 按完整时长检查每一块是否成功，防止只处理第一块、工具默认截短或某块失败后仍拼出“完整稿”。失败区间补转，无法取得的部分明确留作缺口。
- 术语、人名、数值及说话人另行校对。产物应标为“由完整音频生成的 ASR 校对稿”，不能称为官方逐字稿；ASR 生成成功本身不证明覆盖或准确。
- 只有缺口音频无法取得，或所需服务/权限确实不可用时，说明已尝试的路径、缺失区间及需要的材料；已有可独立完成的部分继续整理。

## 6. 留下一份可回溯的来源记录

每期至少保存：原单集链接与版本、核对过的节目元数据、音频来源页面/文件与实际时长、文字来源页面/文件及类型、覆盖核验依据、缺口、获取时间和下一步。临时媒体地址可在受控本地任务记录中保存，公开输出保留稳定来源链接。

文字材料类型可记为“官方逐字稿／官方删节稿／平台字幕／第三方 ASR／本地 ASR／摘要”；覆盖状态单独记为“待核验／有缺口／覆盖已核验”。保留原始材料，不用编辑后的稿件反过来证明来源完整。
