# Podcast Transcript Editor

仓库地址：[wendy57h/podcast-transcript-editor](https://github.com/wendy57h/podcast-transcript-editor)

告诉 AI 你想整理哪期、哪个栏目或哪个方向的播客，优先寻找已有的精校全文或完整转录稿，整理成“开篇简介—核心洞察—全文转写”，再按需交付飞书文档、PDF 或 TXT。

这是一套给 AI Agent 使用的 Skill：从来源核对、说话人校对，到全文编辑、合集导读和阅读文件验收，保留一条可追溯的工作链。

仓库开源工作流、参考说明、版式检查脚本和原创演示样例；不包含实际整理过的播客全集、私人飞书文档、账号配置或成品 PDF。

## 能做什么

- **找到音频与全文**：从小宇宙等单集页、shownotes、官方 RSS/公众号、同期视频字幕和可访问的第三方转写寻找材料，核对同一期及全程覆盖；找不到现成全文时，用完整音频 ASR 接续。
- **整理全文**：校对人名与术语、确认说话人、恢复访谈顺序，保留论证、例子和限制条件。
- **形成读物**：简介、核心洞察、完整对话；按需组织合集顺序和自然段导读。
- **按格式交付**：飞书原位更新、长文 PDF、主章清晰的 TXT，或具有父子目录的 EPUB。
- **说明检查范围**：区分文字校对、局部回听、版式检查和目标 App 实测。

## 输出方式

**只生成你选的格式，可以单选或多选。** 飞书便于在线整理和协作，PDF 适合长文阅读，TXT 便于导入阅读器；需要明确父子目录时可另外选 EPUB。不要求安装飞书，也不会默认给每个人生成所有格式。仓库只包含工作流、检查器和原创文本示例，宣传图片与成品读物单独管理。

## 它是什么，需要什么

这份 Skill 的主体是 `SKILL.md` 与按需读取的参考资料。它指导具备文件、网络和相关工具权限的 Agent 执行任务；**不是独立的一键下载、转写或排版应用**。当前只附带版式检查器，通用音频转写、PDF/TXT/EPUB生成仍由 Agent 按环境选用工具完成。

| 需求 | 所需能力 |
| --- | --- |
| 已有文字稿校对、本地交付 | 支持读取 Skill 的 Agent、文件访问 |
| 搜寻与来源核对 | 可用的搜索或网页工具 |
| 从音频生成全文 | 用户有权使用的完整音频、可用 ASR；音频截取常用 ffmpeg |
| PDF | 可用的排版/打印工具、覆盖中文且可合法使用的字体、PDF渲染与检查工具 |
| TXT | UTF-8文本处理；目录效果仍需目标阅读器导入核验 |
| EPUB | EPUB打包、导航校验；可用时运行 EPUBCheck |
| 飞书 | 当前环境已配置的飞书CLI或连接器与对应权限；不需要飞书也能整理本地文件 |

## 使用方式

### 第一次使用会怎样引导

不必先准备文字稿。你可以给 AI 单期链接、标题、多期清单，要求某栏目的全部节目，或者只给一个感兴趣的方向。

如果没有说清楚范围和格式，AI 会简短询问：

> 你想整理哪期或哪类播客？可以发链接、标题，指定一个栏目的全部节目，或者给我一个方向来推荐。成稿想要飞书文档、PDF 还是 TXT？可以只选一种，也可以多选。

已经给出的信息不会重复问。全栏目任务会先建立截至检索时的单集清单、处理分页并记录覆盖情况；不会把最近几集冒充全部。

随后按这条流程处理：**核对节目 → 优先找精校完整稿 → 找完整音频转录稿/字幕 → 无合适全文时用完整音频 ASR 转写 → 校对并提炼洞察 → 按所选格式交付及验收**。官方微信公众号等材料用于补充核对；若本身提供完整稿，也可直接采用。这里的音频转文字是 ASR，TTS 则是文字转语音。

### 支持本地 Skills 的 Agent

将本仓库作为一个完整的 `podcast-transcript-editor` 文件夹，放到你所用 Agent 的 Skills 目录。该目录中应直接有 `SKILL.md`、`references/`、`scripts/`。不同客户端的发现路径和启用方式，以其当前说明为准。

启动新会话后，可尝试显式调用：

```text
使用 $podcast-transcript-editor 帮我整理播客。
先了解我想要的节目范围和输出格式；如果我已经说明，就直接开始。
优先找已有的完整精校稿或音频转录稿，没有时再从完整音频转写。
```

### 其他 Agent

让 Agent 读取 `SKILL.md`，并按链接读取本次任务需要的参考文件。工具名称和命令需要适配；未对所有 Agent 客户端做兼容性实测。

```text
请整理《{栏目名称}》截至今天发布的全部播客。

每篇按开篇简介、核心洞察、全文转写整理，只输出 TXT。
```

```text
我对具身智能创业感兴趣，还没选具体节目。
请先给我少量播客候选，帮助确定范围；我想做成 PDF 阅读。
```

```text
这是一期小宇宙播客链接：{单集链接}。

检查首尾、各话题和中间是否缺段；没有现成全文就从完整音频转写。
```

具体搜寻路径、检索示例和完整性判断见 [音频与完整文字稿搜寻指南](references/source-discovery.md)。其中 Podwise 等属于可选来源，是否可读取全文取决于实际单集、账号权限与当前工具；本 Skill 不附带这些服务的账号或 API。

```text
我有几期播客，想整理成周末读物。
先核对完整来源，再给我建议顺序和一篇样稿；确认后处理剩余篇目。
```

```text
请以当前飞书文档为准导出，不再润色原文。
PDF要适合长文阅读，洞察区使用淡紫色卡片。
TXT只将导读和每篇访谈设为主章；内部话题保留在章内。
```

```text
我需要明确可跳转的“每期访谈→内部话题”目录。
请在TXT以外制作EPUB，检查导航、锚点和全文覆盖，说明是否实际导入过目标App。
```

## 重要的工作习惯

**全文与摘要分清。** 没拿到完整来源，就不补写“嘉宾原话”；洞察概括与完整对话分开。

**说话人先于润色。** 问号不代表主持人，段落也不一定等于换人；先确认角色，再编辑文字。

**保留当前版本。** 用户已经修改过飞书文档时，重新读取后再导出，不用旧本地稿覆盖。

**TXT控制主章粒度。** TXT没有标准父子目录，内部小标题不应全部升级为“第X章”；想要明确层级时可补EPUB。微信读书的具体识别结果以客户端实测为准。

**文件生成不等于验收。** PDF检查字体、文本、跨页、链接和书签；TXT检查正文与章节标记；EPUB检查包结构和导航。真正做过的检查才写进交付说明。

## 默认成稿样式

- 标题：`嘉宾：内容｜节目 EP.N`。
- 开篇简介：人物、主题和原节目链接。
- 嘉宾核心洞察：与全文可对照的要点。
- 全文文本：按时间顺序分主题，保留说话人标签。
- 飞书默认：主持人整段蓝色加粗、嘉宾普通文字；PDF可按阅读需要重新设计。

这些是可修改的默认值。用户的结构、颜色、详略和授权范围优先，不应为了检查器而强套版式。

## 版式检查器

只依赖 Python 标准库，示例命令在仓库根目录执行：

```bash
python scripts/check_docx_xml.py examples/demo-episode.xml --host 主持人 --guest 嘉宾 --episode-url https://example.org/podcast/demo-001
```

它检查默认区块、洞察列表、章节与角色样式；不验证节目真实性、转写准确性、说话人判断或全文覆盖。示例是虚构对话，`example.org`链接是保留域名上的占位演示，不是真实播客来源。
